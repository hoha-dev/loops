# loops — payload manifest (source of truth for /loops:init and /loops:update)
#
# managed : owned by loops — update may replace the whole file (slots {{...}} re-filled from the repo).
# mixed   : ONLY the blocks between <!-- LOOPS:BEGIN <name> --> ... <!-- LOOPS:END <name> --> belong to
#           loops; the rest belongs to the repo and update never touches it.
# seeded  : generated ONCE by /loops:init, then owned by the repo — update never touches it.
# Skills are never copied into a repo (ADR-0003); they come from the plugin.
# The update itself is `node scripts/loops-update.mjs apply --plugin <dir>`: a three-way merge of each
# managed file (and each marker block of a mixed file) over the base recorded in .loops/ at install
# time; conflicts are staged under .loops/update/, never written into the tree (ADR-0005). A repo may
# list a path under "frozen" in .loops/manifest.json to keep its own version of a managed file.
